# 生成 Docs 与 Components 文档站点提示词

将下方提示词交给代码 Agent 使用前，把 `[参考网站 URL]` 替换为目标网站。

```text
请在当前项目的 main 分支上，为 MyUI 实现 Docs 文档站和 Components 组件文档。

参考网站：[参考网站 URL]

## 分支与项目约束

- 开始前检查当前分支和工作区状态，确认在 main 分支。
- 不要从 ui/easyui 分支合并或复制提交；只以 main 分支现有代码为基础。
- 先阅读项目现有路由、组件源码、registry.json、components.json、package.json 和项目文档，再决定实现方式。
- 本项目使用 MyUI 品牌，组件基于 Radix UI 和 shadcn registry。页面内容必须以仓库中的实际组件、依赖和命令为准，不要编造组件、属性或安装方式。
- 不要添加 Sponsors 页面或导航项。
- 保留现有的 `src/app/globals.css`；新增或调整的样式放在 `src/styles/`，遵循项目现有的 tokens、fonts 和主样式文件组织。
- 代码示例使用浅色高亮主题。
- 未经要求不要提交代码或推送分支。

## 参考网站调研

先浏览参考网站，确认其实际页面结构和交互。至少检查：

- 首页和顶部导航
- Docs 首页、Introduction、Quick Start
- Components 列表页
- 一个组件详情页的完整内容
- 侧边栏、面包屑、分页、页脚
- 桌面和窄屏布局
- 代码块、安装命令、复制按钮、预览和源码切换等交互

参考网站仅作为信息架构、布局、间距、字体层级、边框、颜色、交互和响应式行为的视觉参考。不要复制对方的品牌、文案、图片、插画或专有组件内容。保留 MyUI 的品牌和项目实际内容。

## 实现范围

1. 建立 Docs 页面结构，至少包含 Introduction 和 Quick Start。
2. 建立 Components 列表页，展示仓库中实际可用的组件，并支持参考网站已有的分类、搜索或筛选交互。
3. 为每个实际可用组件生成详情页。详情页内容应从组件源码或 registry 获取，包括：
   - 组件名称和用途
   - 安装命令
   - 可运行的组件预览
   - 源码展示
   - 所需依赖和项目内依赖
   - 有源码依据的属性或使用示例
4. 让导航、侧边栏、面包屑、上一页/下一页、复制命令和预览切换等链接与交互可用。
5. 页面文案和安装命令必须与当前 registry 的发布方式一致。不要只为了复刻参考站而保留对方的组件名或仓库地址。
6. 如果组件源码不能安全地直接预览，提供清晰的源码或安装说明，不要用虚假的演示替代真实组件。

## 视觉验收

- 尽量贴合参考网站的页面结构和视觉比例，包括最大内容宽度、侧栏宽度、标题层级、区块间距、代码块尺寸、卡片布局和页脚位置。
- 使用相同视口对照参考页和本地页面截图，逐页修正明显的偏移和间距差异。
- 保证窄屏下导航、侧栏、代码块和组件预览仍可使用。
- 检查键盘操作、焦点状态和可访问名称。

## 完成标准

- Introduction、Quick Start、Components 列表和组件详情页均可访问。
- 文档内容和命令与当前项目一致。
- 所有站内导航和主要交互有效。
- 运行项目构建和适用的静态检查，并修复由本次改动引起的问题。
- 最后汇报：实现的路由、主要改动文件、验证结果，以及因项目内容与参考网站不同而保留的差异。
```
